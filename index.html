02 Work

Four projects, and what I ran into building them.

01

Multi-page website

Momentum Athletics

A site for a community sports club, spread across five pages so someone can go from the homepage to a specific sport, check the training schedule and find the contact form without getting lost.

Live demo (opens in a new tab) Source (opens in a new tab)
Role
Designed and built it on my own
Built with
HTML, CSS, JavaScript, GSAP
Pages
Home, About, Sports, Schedule, Contact
Build notes

What's in it

  • Five pages sharing one header, one footer and one stylesheet.
  • A scroll driven sport switcher: the list on the right changes the photo held in the sticky column on the left.
  • A looping marquee that speeds up slightly with scroll velocity.
  • A contact form that confirms the submission without leaving the page.

How I built it

I wrote the header, the buttons and the spacing once, in a stylesheet all five pages share, instead of styling each page separately. When I changed the nav later I only had to change one file and every page followed.

What I took from it

Keeping a multi-page site consistent is a structure problem before it's a design problem. Deciding what gets shared, and where it lives, turned out to be the real work.

02

JavaScript app

Task Dashboard

A task manager that still has your list when you come back. Each task can carry a person, a due date, a priority, a category and notes, and the whole list can be searched, filtered and sorted.

Live demo (opens in a new tab) Source (opens in a new tab)
Role
Designed and built it on my own
Built with
HTML, CSS, JavaScript
Storage
Saved in the browser with localStorage
Build notes

What it does

  • Search across the task, the person, the category and the notes at once.
  • Filter by status and priority, sort by date, priority or name.
  • Counters and a progress bar that update as the list changes.
  • Send a task to Google Calendar or Outlook as a prefilled event.

How it's put together

The tasks live in one array and the list on screen is drawn from it. Search, filtering and sorting are small separate functions that run over that array before anything gets rendered, so adding a new filter didn't mean rewriting the rest.

The tricky part

Overdue isn't something you set. It gets worked out from the due date every time the list is drawn, which means a task can go overdue on its own while nobody is touching the page. That took me a while to get right.

Responsive website

Elite Cuts

A barbershop landing page in a dark, warm palette. Services, hours and a booking call to action, with a mobile menu that opens and closes from the same button and shuts itself when you tap a link.

Live demo (opens in a new tab) Source (opens in a new tab)
Role
Designed and built it on my own
Built with
HTML, CSS, JavaScript
Focus
Dark interface and mobile navigation
Build notes

What's in it

  • A sticky header with anchor navigation between sections.
  • Services, opening hours and a booking section.

The menu

One button controls it. It flips a class and updates aria-expanded at the same time, so what a screen reader announces and what you see can't end up saying different things.

What I ran into

Dark interfaces need more contrast checking than light ones. Text that looked fine on my laptop turned out to be too dim once I actually measured it.

04

API integration

Weather App

Search a city, narrow it down by state, and get the current conditions plus a five day outlook from the OpenWeather API. The whole interface switches between English and Spanish without reloading.

Live demo (opens in a new tab) Source (opens in a new tab)
Role
Designed and built it on my own
Built with
HTML, CSS, JavaScript, fetch
Data
OpenWeather API
Build notes

What it does

  • Current conditions with feels like, humidity and wind.
  • A five day forecast built from the API response.
  • Celsius and Fahrenheit, and English and Spanish.
  • The background changes with the weather, so clear, rain and storm each get their own colours.

How the language switch works

All the interface text sits in one object with an English and a Spanish version of every key. Changing the language relabels the page from that object, so there is no duplicated markup and no reload.

The tricky part

Working out what the app should show before anyone has searched, and when a city doesn't exist, took more thought than showing the data. Handling those two cases is what made it stop feeling like a demo.
