02 Client work

01

Client site, built on Wix

Rolling Lawns Farm

A dairy farm in Greenville, Illinois that sells milk and ice cream to markets and restaurants. Their old site was out of date and hard to follow, and they wanted something modern that would help them sell the tours they run at the farm and at the Milk House.

Visit the site (opens in a new tab)
Role
Redesigned and rebuilt their site
Built with
Wix, plus my own HTML and CSS for one section
Focus
Making the tours easy to find and book
Build notes

What they needed

The site they had was static and had almost no colour, and the information on it was old. What they wanted was a page that looked modern and that pushed people towards the tours, because that is what they are trying to sell.

What I did

I rebuilt the layout around the products and the tours, so the tours are not buried at the bottom any more. I added a parallax effect and hover effects on the photos, so the page feels alive instead of flat.

The old site also did not work on phones. I went through it section by section and changed the layout until it did.

The hardest part

One section needed four cards that tilt in 3D when you put the mouse on them. Wix does not have that, and I could not find a way to do it with their editor.

So I wrote those four cards myself in HTML and CSS, with the 3D movement on hover, and embedded them into the page. That was the moment where knowing how to code was the difference between doing it and telling the client no.

03 Projects

Three projects, and what I ran into building them.

01

React storefront

KINETA

A sportswear store with a 28 piece catalogue, filtering and sorting, a cart and wishlist that survive a refresh, and a five step checkout. The homepage opens on a hero that transforms as you scroll: the interface clears, the figures accelerate past the camera, and the wordmark rushes forward and turns to ink to open the store.

Live demo (opens in a new tab) Source (opens in a new tab)
Role
Designed and built it on my own
Built with
React, TypeScript, Vite, Tailwind, GSAP, Three.js
Focus
Application structure and scroll driven motion
Build notes

What it does

  • 28 products you can filter by size and price, and sort by price or newest.
  • A cart and a wishlist that are still there if you close the tab and come back.
  • A checkout with five steps.
  • A home page where the brand name grows until it covers the screen and opens the store.

How I built it

Every page asks for products from one file, repository.ts. Nothing else in the app knows where the products come from. Right now they come from a list I wrote by hand, so the day they come from a real server I change that one file and no page has to change.

I used two animation libraries, but not for the same job. GSAP moves things when you scroll. Framer Motion moves things when you click, like the cart opening. I never use both on the same element, so they can't fight each other.

The hardest part

When I scrolled back up to the top, the screen started blinking and the big KINETA text disappeared.

I was making the text bigger with scale: 24. The problem was that I was growing the whole box around the text, not the text itself, and that box is as wide as the screen. So the browser had to draw a picture about 34,000 pixels wide. Chrome only goes up to 8,192, so it gave up and drew nothing.

I changed it to grow only the text, and used scale: 6. Now the picture is 5,358 pixels wide and it works. It still looks the same, because by then the text is already the same dark colour as the panel behind it.

02

Multi-page website

Momentum Athletics

A site for a community sports club, spread across five pages so someone can go from the homepage to a specific sport, check the training schedule and find the contact form without getting lost.

Live demo (opens in a new tab) Source (opens in a new tab)
Role
Designed and built it on my own
Built with
HTML, CSS, JavaScript, GSAP
Pages
Home, About, Sports, Schedule, Contact
Build notes

What it does

  • Five pages that share the same header, footer and stylesheet.
  • A list of sports where the photo on the left changes as you scroll past each name on the right.
  • A line of moving text that goes a bit faster while you scroll.
  • A contact form that answers you without reloading the page.

How I built it

I wrote the header, the buttons and the spacing one time, in a stylesheet that all five pages use. I did not style each page on its own.

That paid off later. When I changed the menu, I edited one file and the five pages changed with it. If I had copied the styles into each page, I would have had to fix the same thing five times, and I would probably have missed one.

The hardest part

Deciding what should be shared and what should stay on its own page.

At the start I put everything in the shared file, even things only the Schedule page used, and the file got long and confusing. I moved the parts that only one page needed back into that page, and left in the shared file only what really repeats: header, footer, buttons, spacing and colours.

03

Responsive website

Leland Barbers

A barbershop site built to get someone into a chair. Recent cuts swap from the before photo to the after on hover, the shop photos stack as you scroll past them, and the opening hours work out for themselves whether the place is open right now.

Live demo (opens in a new tab) Source (opens in a new tab)
Role
Designed and built it on my own
Built with
HTML, CSS, JavaScript, GSAP
Focus
Image led layout and scroll motion
Build notes

What it does

  • Photos of real cuts that change from before to after when you put the mouse over them, with a button for phones.
  • Photos of the shop that pile on top of each other while you scroll.
  • Prices, opening hours and a form to ask for an appointment.

How I built it

The whole week is one array in the JavaScript, with the opening and closing hour of each day. From that same array the page works out three things: if the shop is open right now, what day and time it opens next, and which row of the table to mark as today.

I did it that way so the hours are written in one place only. If they change on a Saturday, I edit one line and the three things update together.

The hardest part

The photos that pile up while you scroll.

My first version faded one photo into the next. In the middle of the change you could see both at the same time, and it looked like a mistake, like one photo printed on top of another. It did not look like a pile.

What fixed it was cutting the frame so nothing shows outside it, and making each photo slide up from below and cover the one before, with no fading. Now it looks like someone putting photos down on a table.
